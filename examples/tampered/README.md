# Tampered examples

Manipulated copies of [`../transfer-worker.jsonl`](../transfer-worker.jsonl).
In each, someone tries to make record #2, a failed transfer job
(`"status":"failed"`, `reason_code` `transfer.source_not_found`), look like
a successful one, or to remove it. The files show what a verifier reports in
each case. Like the other examples they are generated by
`go/internal/vectors`; `expected.json` lists the verdict, the findings and
the state of every record that every verifier must reach, in the format of
`testdata/streams/expected.json`.

Four files produce one error class each; the manipulated record, or the
one after it, is `invalid`, and so is the journal (exit code 1):

| File | What was done | What `verify` reports |
|---|---|---|
| `hash-mismatch.jsonl` | Record #2 edited in the file; hashes left as they were. | `hash_mismatch` on record #2 (content and chain hash). |
| `chain-break.jsonl` | Record #2 edited and re-sealed, so its own hashes are consistent. Record #3 still links to the original. | `chain_break` on record #3. |
| `seq-mismatch.jsonl` | Record #2 deleted, record #3 re-sealed to link to record #1. | `seq_mismatch` on the record now at index 2: it links to seq 1 but has seq 3. |
| `signature-invalid.jsonl` | Signed journal. Record #2 edited, records #2 and #3 re-sealed, the original signatures copied over. | Without a key: OK. With the producer's public key: `signature_invalid` on records #2 and #3. |

Two files leave a record `unknown` instead. No record in them is provably
wrong, but the journal is `incomplete`, which fails (exit code 3) unless
`--allow-incomplete` is given:

| File | What was done | What `verify` reports |
|---|---|---|
| `seq-gap.jsonl` | Record #2 deleted, nothing else changed. | `seq_gap` on the record now at index 2: it links to a record the journal does not have, so it is `unknown`. |
| `outside-scope.jsonl` | Record #2 edited and its `schema` changed to `trail.evidence/2`, so that a verifier for `trail.evidence/1` does not check it. | `outside_scope` on record #2, `seq_gap` on record #3 (`unknown`). |

Both show why `incomplete` fails by default and why `--allow-incomplete` is
only for journals known to be incomplete, such as rotated logs: with it,
these two manipulations pass (`SPEC.md` sections 6.4 and 6.6).

The signature case is the one section 6.6 of the specification also
describes: whoever controls an unsigned journal can rewrite it so that every
hash and link checks out. A signature binds the chain to a key the editor
does not have. The key here is the published TEST KEY (RFC 8032 test vector
1, in `testdata/keys/`), so anyone can re-sign with it; real producers use
their own key.

## Try it

In the browser verifier, "load a tampered example" opens
`hash-mismatch.jsonl`. Drop the other files on the page the same way; for
`signature-invalid.jsonl` paste the test public key

```
d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a
```

and tick "Allow an incomplete journal" to see `seq-gap.jsonl` and
`outside-scope.jsonl` accepted.

With the CLI, from the repository root (hashes shortened):

```bash
trail-evidence verify examples/tampered/hash-mismatch.jsonl
# INVALID: 4 record(s) in 1 stream(s), 2 error(s)
#   error   hash_mismatch     record #2 (line 3, stream "worker-01", seq 2): content_hash mismatch: recorded sha256:4654569e…, computed sha256:15323e7f…
#   error   hash_mismatch     record #2 (line 3, stream "worker-01", seq 2): chain_hash mismatch: recorded sha256:733544a5…, computed sha256:2ca09585…

trail-evidence verify examples/tampered/chain-break.jsonl
# INVALID: 4 record(s) in 1 stream(s), 1 error(s)
#   error   chain_break       record #3 (line 4, stream "worker-01", seq 3): prev_hash sha256:733544a5… does not match previous chain_hash sha256:2ca09585…

trail-evidence verify examples/tampered/seq-mismatch.jsonl
# INVALID: 3 record(s) in 1 stream(s), 1 error(s)
#   error   seq_mismatch      record #2 (line 3, stream "worker-01", seq 3): seq 3, expected 2: prev_hash links to the record with seq 1, so no record can be missing in between

trail-evidence verify examples/tampered/signature-invalid.jsonl
# VALID: 4 record(s) in 1 stream(s), hash chain intact, 4 signed record(s)

trail-evidence verify examples/tampered/signature-invalid.jsonl \
    --pubkey testdata/keys/test-ed25519.pub --require-signatures
# INVALID: 4 record(s) in 1 stream(s), 2 error(s), 4 signed record(s), 2 signature(s) verified
#   error   signature_invalid record #2 (line 3, stream "worker-01", seq 2): signature does not verify with key ed25519:21fe31dfa154a261
#   error   signature_invalid record #3 (line 4, stream "worker-01", seq 3): signature does not verify with key ed25519:21fe31dfa154a261

trail-evidence verify examples/tampered/seq-gap.jsonl                  # exit code 3
# INCOMPLETE: 3 record(s) in 1 stream(s), no invalid record, 1 unknown
#   notice  seq_gap           record #2 (line 3, stream "worker-01", seq 3): seq 3 after seq 1, and prev_hash sha256:733544a5… does not link to the last checked record: its predecessor is not in this journal

trail-evidence verify examples/tampered/outside-scope.jsonl --allow-incomplete   # exit code 0
# INCOMPLETE (allowed): 4 record(s) in 1 stream(s), no invalid record, 1 unknown, 1 outside scope
#   notice  outside_scope     record #2 (line 3, stream "", seq -): schema "trail.evidence/2" is not trail.evidence/1; the record is not checked and does not take part in any chain
#   notice  seq_gap           record #3 (line 4, stream "worker-01", seq 3): seq 3 after seq 1, and prev_hash sha256:733544a5… does not link to the last checked record: its predecessor is not in this journal
```

Every file except `outside-scope.jsonl` is valid against the JSON Schema;
the manipulation is only visible in the hashes, links, sequence numbers and
signatures. `outside-scope.jsonl` contains one record that names another
major version, which the schema for `trail.evidence/1` does not cover.
